# 0.1.2 — Visible first PWA preparation

Status: prepared for publication. This update requires no existing API renames or application data migrations.

## What changes for users

On the first Service Worker installation, the application now shows an opaque screen using the manifest background, an icon up to 156 × 156 px, and resource preparation percentage. The interface opens after the initial route, startup hooks, cache, and worker activation are ready. This prepares offline resources; it is not a prompt to install the application on a device.

Progress counts verified and stored files, not bytes. It starts at 0% until counters arrive and stays at or below 99% until everything is ready. Subsequent launches with an active worker do not show this screen. A stalled installation releases an otherwise ready application after 60 seconds of visible waiting; an application startup failure displays a Retry button.

The regular update card displays the first 47 Unicode code points of the description, followed by `...` if truncated. The full manifest description is preserved; update actions and activation behavior are unchanged.

## What developers need to do

After the version is published, run these commands in your application directory:

```bash
npm install @solcorp/layer@0.1.2 --save-exact
npm run build
```

Expected result: `package.json` and the lockfile pin 0.1.2, and the new `dist` includes the startup screen. Deploy the complete `dist` following the [deployment guide](../deployment-diagnostics.md), preserving the existing server state directory. Do not clear IndexedDB, sessions, or drafts to upgrade.

The screen is enabled by default. Add this block to your existing `layer.config.js` only if you want to disable it:

```js
export default {
    startup: {
        installationScreen: false
    }
};
```

This is a configuration fragment: keep your other application settings. Worker registration and offline caching still work. The setting is independent of `updates.enabled` and `updates.ui`; `serviceWorker: false` avoids waiting for worker installation. See [initial preparation and updates](../application-updates.md).

## Documentation and security

Release history is now available in the `updates` folder in Russian and English, on GitHub and offline through `npx layer guide`. Every npm package README includes a new-version summary and a link to details.

A vulnerable development-tool dependency is fixed by pinning `minimatch` 11.0.1. No application security settings need to be relaxed. The Node.js minimum remains 24.22.1 in the 24 series, with npm 11.

## Common questions

- **No startup screen:** the application may already have an active worker; normal updates use the existing card.
- **Progress stays unchanged:** file sizes differ, and counters advance after each file is verified. This is not a network speed measurement.
- **An old page remains open:** it initially runs the old runtime. New behavior appears after switching builds; save input before updating.
- **npm returns 404:** check whether the exact version is published. Do not install temporary placeholder packages.
