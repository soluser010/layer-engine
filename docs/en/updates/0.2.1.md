# 0.2.1 — Important security update

The development server now blocks reads outside the project output. Builds and client API generation enforce stricter input checks. Production bundles include Caddy 2.11.9 and keep long-lived event streams open. Update the CLI and rebuild your application.

- **Development and build.** The development server serves regular files inside its output directory. Component, CSS and asset reads verify and read the same open file. Environment files are excluded from build output. Each build gets private staging and rollback directories. A failed restoration preserves the recoverable backup.
- **Operations and PostgreSQL.** Generated client methods validate operation names, types, schemas, reserved keys and collisions in JavaScript and type declarations. Invalid contracts fail the build with a diagnostic. The PostgreSQL driver moves from 8.16.3 to 8.23.1. Testkit handles special JSON keys as own data fields.
- **Deployment and events.** Official Caddy 2.11.9 archives are pinned by SHA-512 for four platforms. The upgrade includes fixes for path handling, proxy headers and TLS configuration. The `write_idle 30s` setting bounds stalled client writes. A POST event stream can wait longer than 30 seconds for its next event.
- **Authentication.** The handbook clarifies application responsibilities for managed account registration, phone challenge verification and private OAuth signing keys. Clients obtain verification keys through `jwks_uri`.
- **Release checks.** Added fast-check, CodeQL and Gitleaks checks, tenant isolation tests and checks on package archives. CI audits against the official npm registry and retains a CycloneDX dependency inventory. The live reload test host handles rebuild failures and the suite checks long streams through real Caddy. License notices for Lightning CSS and Web Push dependencies have been clarified.

## Upgrade

Run these commands in the application directory.

```sh
npm install @solcorp/layer@0.2.1
npm run build
```

Deploy the new `dist` and restart the application with the existing state directory. Previously deployed bundles keep their pinned Caddy until replaced.
