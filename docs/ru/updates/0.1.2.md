# 0.1.2 — Видимая первая загрузка PWA

Статус: подготовлено к публикации. Это обновление не требует переименования существующих API или миграции данных приложения.

## Что изменилось для пользователей

При первой установке Service Worker приложение теперь показывает непрозрачный экран с фоном из manifest, иконкой до 156 × 156 px и процентом подготовки ресурсов. Интерфейс открывается после готовности первого маршрута, startup hooks, кэша и активации worker. Это подготовка офлайн-ресурсов, а не предложение установить приложение на устройство.

Процент считается по проверенным и записанным файлам, а не по байтам. До получения данных отображается 0%; до полной готовности — не более 99%. При повторном запуске с активным worker этот экран не появляется. При зависании установки готовое приложение освобождается после 60 секунд активного ожидания; ошибка запуска самого приложения показывает кнопку «Повторить».

Описание в обычной карточке обновления ограничено первыми 47 Unicode-символами. Если текст длиннее, добавляется `...`. Полное описание в manifest сохраняется; кнопки и процесс применения обновления не изменены.

## Что нужно сделать разработчику

После публикации версии выполните в каталоге приложения:

```bash
npm install @solcorp/layer@0.1.2 --save-exact
npm run build
```

Ожидаемый результат: `package.json` и lockfile закрепляют 0.1.2, новый `dist` содержит стартовый экран. Разверните весь `dist` по [руководству deployment](../deployment-diagnostics.md), сохраняя существующий каталог состояния сервера. Не очищайте IndexedDB, сессии или черновики для обновления.

Экран включён по умолчанию. В существующем `layer.config.js` добавьте этот блок только если требуется отключить его:

```js
export default {
    startup: {
        installationScreen: false
    }
};
```

Это фрагмент конфигурации: сохраните остальные настройки своего приложения. Регистрация worker и офлайн-кэш продолжат работать. Настройка независима от `updates.enabled` и `updates.ui`; `serviceWorker: false` исключает ожидание установки worker. Подробнее: [первоначальная установка и обновления](../application-updates.md).

## Документация и безопасность

История версий теперь доступна в папке `updates` на русском и английском языках, в GitHub и офлайн через `npx layer guide`. В README каждого npm-пакета есть блок о новой версии и ссылка на подробности.

Исправлена уязвимая зависимость инструментов разработки: закреплён `minimatch` 11.0.1. Настройки безопасности приложения ослаблять не требуется. Минимальная версия Node.js остаётся 24.22.1 в ветке 24, npm — 11.

## Типовые вопросы

- **Не виден стартовый экран:** у приложения уже может быть активный worker; обычное обновление использует прежнюю карточку.
- **Процент долго не меняется:** файлы имеют разный размер, счётчик меняется после проверки каждого файла. Это не измерение скорости сети.
- **Старая страница ещё открыта:** сначала она работает на старом runtime. Новое поведение появится после перехода на новую сборку; сохраните ввод перед обновлением.
- **npm возвращает 404:** проверьте публикацию точной версии. Не устанавливайте временные placeholder-пакеты.
